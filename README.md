# 飲食店向け・オーダー管理システム

アルバイト先の飲食店の業務を効率化するためのWebアプリケーションです。  
注文管理・席管理などを一元化しています。

社員との話合いも行い、実際に店舗に導入し、運用する予定です。

---

# 背景

私のアルバイト先の店舗では、紙の伝票による注文管理を行っており、2階で受けた注文を口頭で1階へ伝える必要があったため、繁忙時には伝達の遅れや内容の漏れが発生していた。

私はその原因が、注文情報をリアルタイムで共有できる仕組みがないことであると考え、業務改善のために本システムの開発に取り組んだ。

開発にあたっては、スタッフや社員へのヒアリングを行い、「あると便利な機能」や「運営上必要な機能」を整理した上で、注文の即時共有や一覧表示、操作の簡略化などの機能を実装した。

---

## 技術スタック

- Frontend: JavaScript React  
コンポーネント単位で画面を構築でき、再利用性や保守性の高いUIを実現しやすいため採用した。また、状態管理による動的な画面更新にも適していると考えた。

- Backend: Python FastAPI  
これまでの個人開発でも利用しており、API開発を効率的に進められることに加え、型ヒントや自動生成されるAPIドキュメントにより保守性の高い開発ができると考えた。

- Database: PostgreSQL  
同時アクセス性能に優れており、複雑なデータ管理や拡張性にも優れているため採用した。

- Authentication: JWT
- ORM: SQLAlchemy
- websocket  
新規注文送信時にリアルタイム更新機能が必要だと考え、採用した。

## 機能一覧

### ユーザー機能
- ユーザー登録申請
- 登録申請の許可　/ 却下
- ログイン / ログアウト（JWT認証）
- 権限制御（管理者 / スタッフ）

### 業務関連
- カテゴリー、メニュー一覧表示
- 注文登録・変更・削除
- 注文情報の確認
- 席の状態（使用中・空席など）を確認
- 日本酒の情報を閲覧
- 合計金額を取得

↓（管理者機能）
- 注文の削除・金額変更
- 会計
- 席の設定・管理
- メニューの設定・管理
- 日本酒情報の設定・管理
- ユーザーの管理

---

## 工夫した点

- JWT認証を用いたログイン機能を実装し、安全な認証・認可を実現
- 管理者とスタッフで利用できる機能を制限し、権限管理を実装
- データベースに保存する情報を必要最小限に抑え、保守性を考慮
- バックエンドとフロントエンド間でやり取りするデータを整理し、API設計を最適化
- モジュール間の依存を抑えた疎結合な設計を採用
- 機能追加や仕様変更に対応しやすい拡張性の高い設計を意識
- スタッフや社員へのヒアリングを行い、現場で使いやすいUI・操作性を追求
